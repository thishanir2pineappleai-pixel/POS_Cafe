2. Request conventions and authentication

Send Content-Type: application/json for JSON bodies. Required schema fields are marked *. Optional fields are marked ?. Path identifiers are positive integers unless otherwise noted. Send Authorization: Bearer <token> for protected routes. Login returns data.token, not data.accessToken. No refresh-token endpoint is implemented.

Account roles are owner and admin internally; user DTOs display Owner or Admin. Staff role labels such as Cashier are separate records and do not enable staff login. Owners have all Staff Management permissions. Admins may view/add/edit but may not delete; salary, EPF/ETF and staff documents are owner-only. Roles/teams/permission changes and all Payroll endpoints are owner-only.

Staff shop selection uses ?shopId within the caller?s account; omission selects its lowest-ID shop. No shop yields empty reads and conflict responses for writes. Other-account resources are generally hidden with 404. Protected service requests validate JWTs and confirm sessions with Auth; unavailable dependencies can produce 503.

Menu requires a token only when MENU_REQUIRE_AUTH=true; development defaults to false, production requires true. Menu data is not yet shop-scoped. Legacy Sales endpoints are currently public. Legacy and service storage/session sets are separate: do not assume a gateway-issued token or service record works on port 4000.

3. Responses, pagination and errors

{
  "success": true,
  "data": [],
  "meta": {
    "total": 0,
    "page": 1,
    "limit": 10,
    "totalPages": 1
  }
}

Success envelopes contain success=true with optional message, data and meta. Creation actions generally return 201; reads, updates, deletes, login and logout generally return 200. Some message-only actions omit data. Pagination applies only where the endpoint lists page/limit. Defaults: page=1, limit=10, maximum limit=100; an empty result still reports totalPages=1.

{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "Validation failed",

    {
      "field": "email",
      "message": "Must be a valid email address"
    }
  ]
}

Error example wording is illustrative; clients should use code and field rather than depend on exact message text. CSV and binary file downloads are not wrapped in JSON.

Route source: backend/services/auth-service/routes/v1/authRoutes.js

POST /auth/logout and GET /auth/me require Bearer authentication even though other Auth routes are public. Logout revokes the current session. GET /auth/me returns the user DTO plus shops [{id,name}], and can fail with 503 if Settings is unavailable.

Signup order: credentials ? email verification ? owner details ? phone verification ? business details ? access-key activation ? login. Keep registrationToken from credentials and send it in the JSON body of intermediate steps. Next-step values are email_verification, owner_details, phone_verification, business_details, access_key and login. Activation accepts email and accessKey; it does not log the user in.

Credentials returns 201 with registrationToken, expiresAt, nextStep and delivery. Verify operations return nextStep; owner/business steps also report delivery. Resend operations report delivery or deliveryConfigured. Activation returns data.activated=true. Password-reset verification returns data.resetToken and expiresInSeconds; reset accepts that token and invalidates sessions after a successful password change. The new password must differ from the existing one.

Passwords: 8?128 characters containing uppercase, lowercase, number and symbol, without spaces. OTP codes are strings with six digits and expire after 3 minutes; maximum five wrong guesses, one-minute resend cooldown, maximum five sends/hour. Registration lifetime: 24 hours. Access key: 72 hours. Reset token: 10 minutes. Default session: 12 hours; keepSignedIn=true: 30 days. Limits are current configurable policy defaults.

No production email/SMS provider is configured. MESSAGE_DELIVERY=none does not deliver codes. For local testing only, MESSAGE_DELIVERY=dev-outbox exposes GET http://127.0.0.1:4001/api/v1/dev/outbox directly on Auth (not forwarded by the gateway). This mode is refused in production. Do not expect raw OTPs or access keys in public API responses.

13. Uploads and exports

Upload image with multipart/form-data field image, JPEG or PNG, at most 2 MiB. Upload staff documents with field document and slot cv (PDF/DOC/DOCX), idCopy (JPEG/PNG/PDF), or agreement (PDF), at most 5 MiB. Types are inspected from bytes; filenames are generated by the server. Staff files are private. Public product/shop/admin image paths are under /uploads/products, /uploads/settings, /uploads/admins; these are origin-level paths outside /api/v1.

Staff CSV endpoints require format=csv explicitly: validators accept optional format, but the CSV response helper rejects any value other than csv, including an omitted format. PDF/XLS respond 501. Legacy order exports default to CSV when format is omitted. Successful CSV downloads use text/csv and Content-Disposition: attachment; staff exports use no-store.

curl -X POST "http://127.0.0.1:4100/api/v1/products/1/image" -H "Authorization: Bearer <token>" -F "image=@product.png"
curl "http://127.0.0.1:4100/api/v1/attendance/export?date=2026-10-22&format=csv" -H "Authorization: Bearer <token>" -o attendance.csv

16. Health, local testing and limitations

Gateway and each service expose GET /health on their own origin. Health JSON reports service identity/status; it does not establish all business dependencies are reachable. Gateway /health is not /api/v1/health. Conditional development outbox routes must be accessed on Auth directly or on the legacy origin with that mode enabled.

Gateway defaults: 600 requests per minute per client IP, 15-second upstream timeout, 10 MiB body cap. Services parse JSON with a 100 KiB limit. Endpoint-level rate limits may be stricter; counters are process-local. Per-user staff write/upload limits are defined in staff service configuration. Defaults may be changed by environment/policy settings.

No implemented public API should be inferred from empty placeholder controllers/routes for customers, inventory, suppliers, payments, refunds, tables/QR, or external notification integrations. No refresh token, staff login, public order creation, category edit/delete or discount-definition edit/delete route is registered in the inspected services. MySQL persistence requires REPOSITORY_DRIVER=prisma and deployed service migrations; memory mode loses data on restart.
